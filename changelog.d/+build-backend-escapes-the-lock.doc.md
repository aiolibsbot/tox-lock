No lock reaches the build backend. Before either of the two `pip` invocations that install a packaged project, `tox` installs whatever `[build-system] requires` names into a packaging env -- and `constrain_package_deps` is read on neither of them, while `deps`, the key a lock is ordinarily carried on, `tox` refuses on a PEP 517 packaging env outright. So the code that runs first in the build is the code nothing pins. The README now says so, and gives the way in: a lock compiled out of a copy of that table and named in `constraints` on `[pkgenv]`, with the honest limit that `pip` reads a constraints file for pins and ignores the hashes beside them.
